# คู่มือสาธิตปฏิบัติการสัปดาห์ที่ 12

## ก่อนเริ่มนำเสนอ

1. เปิดโฟลเดอร์โปรเจกต์ `C:\ApiWork\student-api` ใน VS Code
2. ตรวจว่า MySQL และ Redis ที่โปรเจกต์ใช้อยู่เปิดทำงานแล้ว
3. เปิด Terminal แรกแล้วสั่ง `npm run dev` ค้างไว้
4. เปิด Terminal ที่สองแล้วสั่ง `npm test -- --runInBand` เพื่อแสดงผลทดสอบ
5. ใน Postman เลือก environment `student-api-wk12-local` และ collection `WK12 Validation and Rate Limiter`

## ลำดับสาธิตและบทพูด

### 1. Schema และผล Jest

เปิด `schemas/studentSchema.js` แล้วอธิบายว่า Zod ตรวจชนิดและรูปแบบของ name, major, email และใช้ `superRefine` บังคับให้สาขาที่ขึ้นต้นด้วย `International` ต้องมี `passportNumber` จากนั้นแสดงผล Jest ว่าผ่าน 8 suites รวม 31 tests

### 2. ทดสอบ Validation

ใน Postman ส่ง `POST http://localhost:3000/api/v1/students` โดยใช้ major `International Business`:

- ไม่ใส่ `passportNumber`: คาดหวัง `400 Bad Request` และรายละเอียดระบุ field `passportNumber`
- ใส่ `passportNumber`: คาดหวัง `201 Created`

อธิบายว่า passportNumber ใช้ตรวจเงื่อนไข ส่วนข้อมูลที่บันทึกลง student คือ name, major และ email

### 3. อธิบาย Rate Limiter และโควตาแยก

เปิด `middlewares/rateLimiter.js` เพื่อชี้ค่าและ header configuration แล้วเปิด `app.js` ให้เห็นตำแหน่ง mount: `generalLimiter` ครอบ request ทั่วไป และ `authLimiter` อยู่ก่อนเส้นทาง login `/api/v1/auth/login`

แสดงหลักฐาน Postman ที่ login ได้ `429` แล้ว `GET http://localhost:3000/api/v1/students` ยังได้ `200 OK` เพื่ออธิบายว่า limiter ทั้งสองแยกโควตากัน

### 4. สาธิต Brute-force

เปิด Postman Runner เลือก request `POST Login - Brute force` ตั้ง Iterations เป็น 20 แล้วเริ่มรัน ผลควรเป็น `401` ใน 5 คำขอแรก และ `429 Too Many Requests` หลังใช้โควตาครบ

คลิกผล `429` เปิดแท็บ Headers และชี้ `RateLimit: limit=5, remaining=0, reset=...` พร้อมอธิบายว่าใช้ครบ 5 ครั้งแล้ว และ reset คือนับถอยหลังโดยประมาณก่อนเริ่มโควตารอบใหม่

## ปัญหาที่พบและวิธีแก้

ระหว่างเริ่ม server เคยพบ Redis `ECONNREFUSED 127.0.0.1:6379` เพราะ Redis ยังไม่พร้อมใช้งาน หลังเปิด Redis แล้ว server เชื่อมต่อฐานข้อมูลได้และทดสอบต่อได้
